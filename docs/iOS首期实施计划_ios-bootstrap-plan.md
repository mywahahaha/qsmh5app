# iOS首期实施计划

日期：2026-11-02。范围由用户确认：创建 iOS 工程，完成初始化、隐私、H5 登录、游戏容器和基础 Bridge，并通过模拟器及替身测试。

## 本轮交付

1. Swift + UIKit + WKWebView 独立工程，最低部署目标暂用 iOS 16；最终游戏身份、Bundle ID 与方向等待实际材料。
2. Debug-Local、Debug-Integration、Release 隔离；本地 endpoint、状态重置和认证替身仅编入 Debug-Local。
3. 初始化严格解析、六项 Header、隐私前设备码/Token 为空、隐私拒绝说明与重新选择。
4. Keychain Token、应用内随机安装标识、Token 自动登录和 H5 登录成功通知；同一串行会话边界内校验并提交 Token。
5. WKWebView 容器与基础 Bridge；按实例、文档、主 frame、精确 origin、会话代次授权；关闭立即失效。
6. 本地 HTTP/H5 服务、认证 Gateway 替身、单元与真实 WebView UI 回归；模拟器构建运行与设备架构编译。
7. 补充材料检查入口，记录签名、设备和官方阿里云 SDK 的待办及实际状态。

## 基础 Bridge 范围

本轮实现隐私同意/拒绝/撤回、H5 登录成功、Token/游戏信息、logout、配置内窗口打开/关闭、当前页面关闭、游戏 URL 切换及通用存储。保留 requestPhoneLogin 适配边界；缺少真实 SDK 时明确失败并回退 H5。SDK 展示和业务登录成功分开处理。

角色、悬浮球、运营心跳、完整更新 UI、真实 SDK 品牌授权页及多游戏出包属于后续模块；未实现的方法返回明确错误，不以成功返回掩盖。

## 顺序与验收

- P1：工程、配置、解析、API、持久化与状态编排；先用替身覆盖失败和过期响应。
- P2：原生页面、WKWebView、注入脚本与来源策略；完成真实页面闭环和窗口保留。
- P3：本地测试服务、XCTest/XCUITest、构建脚本；记录命令、结果、平台与证据路径。
- P4：核对用户提供的签名/设备/SDK 材料，能完成的接入立即推进；缺少外部材料时保留可运行的 H5 主流程，并准确记录阻塞。

至少覆盖缺 code/类型错误、HTTP 错误、隐私前后 Header、拒绝/重启/撤回、登录持久化、logout 旧结果失效、来源拒绝、非对象参数保留 id、跨窗口/关闭/导航后的失效，以及本地测试入口不能影响正式配置。
