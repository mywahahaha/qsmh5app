# 初始化接口字段说明

更新日期：2026-11-12。本文说明初始化接口的已确认字段，业务流程以 [安卓 H5 游戏包开发需求文档](../安卓H5游戏包开发需求文档_requirements.md) 为准。此前版本用户已确认完成 Android 真机测试，具体进度与历史验证记录见[安卓工程构建与联调指南](安卓工程构建与联调指南_android-build-and-integration.md)。本次补充 Android 悬浮球从隐藏恢复显示时的重新定位规则；宽高 dp、`top/bottom` 优先级及比例/dp 规则以下文为准。

## 请求与响应

- 方法：`POST`。
- 固定地址：`https://box.74meng.com/h5_app/init`，不可被初始化响应覆盖。
- 当前客户端请求体：`{}`。
- 固定 Header：`Gameid`、`Devicecode`、`Packagecode`、`Devicetype`、`Accountoken`、`Gameversion`、`Notchscreen`、`Screenmode`。`Notchscreen` 为 Android 系统报告有刘海或挖孔时的 `1`，否则为 `0`；游戏 WebView 延伸到缺口区域，H5 可通过 `getGameInfo.data.notchScreen` 取得同一状态自行适配。`Screenmode` 按当前应用方向发送，横屏为 `horizontal`、竖屏为 `vertical`，与 `getGameInfo.data.screenMode` 一致。其他 Header 无值时仍发送空字符串；未同意隐私协议前 `Devicecode`、`Accountoken` 为空。
- `Gameversion` 来自构建时填写的游戏版本，渠道分包只写入 `Packagecode`，不会更改游戏版本。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | number | `0` 成功；非 `0` 停止启动 |
| `msg` | string | 非 `0` 时显示“游戏初始化失败：”加此文案；JSON Unicode 转义自动还原为中文，缺失或空白时才回退显示错误码 |
| `data` | object | 成功配置；失败响应不要求提供 |
| `data.bgImage` | string | 可选 H5 底层背景绝对地址，等比例铺满；区别于本地启动闪图 |
| `data.updateInfo` | object | 更新窗口及处理方式，详见下节 |
| `data.jumpDomain` | string[] | 游戏内跳转到外部浏览器的精确主机白名单；不用于更新地址校验或 Bridge 来源校验 |
| `data.aliyunOnekeyConfig` | object | 阿里云一键登录配置，`open=1` 开启；完整子字段、默认值、样式与 iOS 参考见[一键登录独立需求](阿里云一键登录独立需求_aliyun-onekey-login.md) |
| `data.popupInterval` | object | 运营心跳地址 `url` 及秒数间隔 `interval` |
| `data.floatball` | object | 悬浮球初始显隐、图片、尺寸与位置，Android 规则及 iOS 适配详见下节 |
| `data.privacyAuto` | boolean | 尚未同意隐私时是否先显示协议页面；`false` 跳过并本地标记已同意 |
| `data.h5Pages` | object | 页面配置，以 `agreement/login/welfare/game` 映射页面实例及布局 |

## 悬浮球字段 `data.floatball`

本节尺寸换算默认描述 Android；iOS 使用相同字段、优先级和运行状态，平台坐标映射见下方“iOS 适配”。

```json
{
  "show": true,
  "image_default": "https://example.com/floatball.png",
  "image_active": "https://example.com/floatball-active.png",
  "width": 20,
  "height": 20,
  "right": 10,
  "top": 0.2,
  "bottom": 200
}
```

该示例设置 20dp × 20dp 的球体控件，使用 `top=0.2`，忽略 `bottom=200`。字段作用于初始布局；显示期间拖动后使用拖动位置，容器尺寸变化时按初始化配置重新计算。Android 每次从隐藏恢复显示时也按初始化配置和当前实际可见区域重新计算，不恢复隐藏前的拖动位置。

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `show` | boolean | 可选，默认 `false`；登录且游戏加载后才允许显示 |
| `image_default` / `image_active` | string | 必填，默认/激活状态的图片地址；支持静态图片及动态 GIF，按实际格式识别 |
| `width` / `height` | 正整数 | 必填，单位为 dp，仅按设备 density 转换为布局所需的 px，不按窗口宽度缩放 |
| `left` / `right` | 整数 | 可选，沿用 360 宽设计基准缩放；`left` 优先，两者均缺失按 `right=0` |
| `top` / `bottom` | 非负有限 number | 可选；`top` 存在则完全忽略 `bottom`，包括其类型和数值；两者均缺失按 `top=0`。仅对生效字段校验数值，字符串、布尔、`null`、负数及溢出为非有限数值均拒绝 |

### 垂直位置与边界

- `0 < 值 < 1`：按当前悬浮层完整高度计算距离，`0.2` 为高度的 20%，不是字符串 `"20%"`，也不是可拖动行程的 20%。
- `值 = 0`：贴对应边缘；`值 ≥ 1`：单位为 dp，可为小数，先乘设备 `density` 转成 px，不按窗口宽度缩放。`1` 与 `1.0` 均表示 1dp。
- 设悬浮层高度为 `H`、dp 转换并限制后的球体高度为 `h`（均为 px）、生效距离为 `d`：比例值计算 `d = 值 × H`，其他值计算 `d = 值 × density`。选 `top` 时，球体上边缘 `y = d`；仅有 `bottom` 时，`y = H - h - d`。
- 最终 `y` 限制在 `[0, H-h]` 并向下取整。球体宽高也限制在容器内，避免比例接近 1 或绝对距离过大时越界。比例 100% 不通过 `1` 表示；如需贴底，应只传 `bottom=0`。
- 容器优先采用悬浮层实际宽高，首次尚未布局时回退到窗口像素尺寸。窗口变化后重新计算；不另行增加状态栏、刘海或手势区的间距。
- Android 每次悬浮球从隐藏恢复显示时，先保持不可见，使用初始化定位字段和当前实际可见区域重新计算坐标；定位完成后再显示，避免从旧方向或旧拖动位置跳到新位置。该规则不改变运行时 `show/active` 状态。

例如 `H=1000px`、`h=100px`、`density=3`：

| 配置 | 球体上边缘 y | 说明 |
| --- | --- | --- |
| `top=0.2, bottom=200` | 200px | top 优先 |
| 仅 `bottom=0.2` | 700px | 球体下边缘距底 200px |
| `top=0, bottom=0.2` | 0px | 0 也是已提供的 top |
| 两者缺失 | 0px | 默认顶部 |
| 仅 `top=1` | 3px | 1dp × density |
| 仅 `top=20` | 60px | 20dp × density |
| 仅 `bottom=20` | 840px | 球体下边缘距底 60px，即 20dp |
| 仅 `bottom=0` | 900px | 球体贴底 |
| 仅 `top=0.99` | 900px | 计算值 990px 限制为完整可见位置 |

### iOS 适配

- `width/height` 为正整数，直接映射 pt，不乘屏幕倍率、不按窗口宽度缩放；`left/right` 仍按容器宽度 `W / 360` 缩放，left 优先，默认 right=0。
- 悬浮层采用当前 safeArea，`H` 为该容器完整高度，`h` 为已限制到容器内的球体高度，单位均为 pt。`0 < 值 < 1` 时 `d = 值 × H`，其余合法值直接为 pt；top 优先（含 0），仅 bottom 时 `y = H - h - d`。坐标 clamp 后向下取整，不再额外叠加安全区边距。
- 仅纵向拖动，普通显隐和图标切换保留本会话位置；容器尺寸变化按原配置重算。图片等比例显示，iOS 当前 GIF 使用首帧；Android 本次更新已支持 GIF 动画，iOS 动画播放尚未同步。
- 登录有 Token 且游戏主文档提交后才显示；福利置顶临时隐藏，关闭福利或游戏置顶按最后有效 `show/active` 恢复。退出、关闭游戏和重新初始化复位初始 show、active=false。
- `popupInterval` URL 有效且 interval 为正整数时，在球首次实际显示后等待完整间隔，POST `{}`，附六项基础 Header；iOS 另附 `Notchscreen` 和 `Screenmode`。一次完成再计下一周期。隐藏或福利遮挡后继续轮询；退出/关闭游戏停止并丢弃旧响应。iOS 退后台暂停，回前台重新等待完整周期，已启动会话即使球隐藏也可恢复轮询。
- 本轮 iOS 仅处理成功响应 `data.floating_ball={show:boolean,active:boolean}`；缺失或无效状态保留旧值，`popup_pages` 尚未实现，不代表运营窗口同步完成。

完整需求对照及测试见 [iOS悬浮球记录](iOS悬浮球需求与实现_ios-floating-ball.md)。

### 为什么宽高与 PC 的同数字像素观感不同

初始化返回的整数宽高单位为 **Android dp**，不是图片文件像素。原生 `LayoutParams` 接收 px，代码先按设备密度转换：

```text
实际宽或高 px = floor(配置 dp 值 × density)
```

最终宽高分别限制在容器宽高内，最小为 1px。宽高不再按 360 宽设计基准缩放；相同 density 下，只要容器足够容纳球体，横竖屏和窗口宽度变化不会改变它的 dp 尺寸。

- `width=20,height=20`：`density=1` 时为 20×20px，`density=2` 时为 40×40px，`density=3` 时为 60×60px，均表示 20dp × 20dp。
- 同一设备从 1080px 宽竖屏切至 1920px 宽横屏，若 `density=3`，球体仍为 60×60px；窗口尺寸不参与宽高换算。
- 网络图像通过 `FIT_CENTER` 等比放入控件，比例不同或图片有透明留白时，可见图案会比控件边框小。原图分辨率主要影响清晰度，不直接决定控件尺寸。动态 GIF 保留帧动画，按素材时长与循环设置播放；隐藏/后台暂停，显示/前台恢复，切换图标和销毁视图时清理旧请求。
- PC 浏览器通常用 CSS px；页面缩放、系统缩放和 `devicePixelRatio` 会影响其物理像素数量。手机像素密度也不同，同样数量的物理像素并不保证相同的物理尺寸，不能只比较数字。

`left/right` 本次继续使用原有 360 宽设计基准缩放，单独计算：`screenWidthDp = floor(容器宽 px / density)`，水平间距 px 为 `floor(配置值 × screenWidthDp / 360 × density)`；其优先级不变。PC 预览应按 dp 设计尺寸和目标密度模拟，不应把接口的 `20` 直接当作手机上的 20 个物理像素。

### 旧包迁移

此前 Android 采用 `bottom` 优先，宽高和垂直间距均按 360 宽设计基准缩放。本次最终规则为 `top` 优先、宽高直接按 dp、`top/bottom ≥ 1` 按 dp；此前同日草案中的“物理 px 直用”已被本次 dp 约定替代。原 `width/height` 及仅传 `bottom=200` 等配置的实际显示可能变化，应按 dp 核对。客户端须重新构建并安装 APK；旧 APK 和仅重新渠道分包的旧母包不会应用新布局。

## 更新字段 `data.updateInfo`

```json
{
  "open": 0,
  "width": "50%",
  "height": "auto",
  "popup": 1,
  "force": 0,
  "title": "",
  "time": "",
  "desc": "",
  "version": "",
  "url": ""
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `open` | number | `0` 跳过更新并忽略其余字段；`1` 显示原生更新窗口 |
| `width` | number / string | 纯数字或数字字符串按 Android dp 直用，例如 `50`、`"50"` 为 50dp；仅带 `%` 的字符串按完整窗口宽度百分比直用，例如 `"50%"` 为 50%；不额外乘缩放系数。数值须大于 0，百分比不超过 100% |
| `height` | number / string | 与 `width` 同一单位规则：`50`、`"50"` 为 50dp，`"50%"` 为窗口高度的 50%；`"auto"` 不指定固定高度，按实际内容自适应；不额外乘缩放系数 |
| `popup` | number | `1` 通过外部浏览器打开 `url`；`0` 在应用内部下载 APK 并请求系统安装 |
| `force` | number | `1` 正常更新不可关闭且无下方关闭按钮；`0` 可关闭并继续启动 |
| `title` | string | 头图上的白色标题 |
| `time` | string | 更新时间，按服务端字符串展示 |
| `desc` | string | 面板中的红色更新说明 |
| `version` | string | 目标版本文案；为空时弹窗显示“最新版本：未提供”，不能据此推断目标版本；不会覆盖本次运行的游戏版本 Header |
| `url` | string | 绝对 HTTP/HTTPS 地址；`popup=0` 必须返回 APK 文件，`popup=1` 可返回外部更新页面 |

### 窗口与下载安装

- 原生绘图，头部使用随包 `bg.png`，白色面板圆角按 Android 15dp 适配；底层黑色遮罩透明度 45%。百分比尺寸相对完整窗口计算，dp 尺寸直接按屏幕密度换算，均不额外乘 0.7；内容过长时在面板内滚动并保留关闭控件空间。
- `version` 有值时，版本与时间显示为“最新版本：1.0.2  更新时间：2026-11-05”，两项同排间隔 15 物理像素；空间不足时分行完整显示。服务端 `version` 为空而 `time` 有值时，显示“最新版本：未提供”和更新时间；准确版本须由服务端填写 `updateInfo.version`，客户端不使用当前安装包版本冒充目标版本。
- 相对上一版，常规标题栏高度减少约 20%，背景图可拉伸填充；主按钮高度在上一版基础上增加 10 物理像素，按钮下方留白缩减约一半。关闭按钮在翻倍后的尺寸基础上，宽高各缩小 20%；最小尺寸约为 35dp × 35dp，背景为纯黑 `#000000`，图标为白色 `#FFFFFF`。
- `title/time/desc/version` 均为字符串，允许空字符串；标题、说明和时间为空时对应文案隐藏，版本为空且时间也为空时整行隐藏。`open=1` 的 `url` 必须有效且非空。各开关均为数字 `0/1`，不使用布尔值或字符串开关。
- “立即更新”为绿色圆角按钮；`force=0` 时下方显示圆形关闭按钮。
- 点击遮罩不关闭窗口；`force=1` 拦截返回键。外部浏览器打开成功后，`force=0` 结束更新并继续登录，`force=1` 保留弹窗，返回游戏后可再次更新。
- 内部下载显示渐变进度条和百分比。下载完成后保留进度，并显示同款“立即安装”按钮，同时自动请求系统安装；需要未知来源安装授权时保留该入口，拒绝授权后可再次点击。
- 安装器以独立任务打开，成功唤起后退出并移除游戏任务，不继续进入登录。打开安装授权设置时不退出；授权返回后成功唤起安装器才退出。启动设置或安装器失败时提示并按现有异常策略继续登录。安装完成或取消后，从桌面重新启动将重新初始化；外部浏览器更新流程不受影响。
- 退出游戏任务使用 Activity 结束流程，不强杀进程、不立即删除已下载 APK，保留安装器通过 FileProvider `content://` URI 读取的条件。成功发起安装不代表系统已安装成功，签名、版本兼容与用户确认仍由系统处理。
- Android 8+ 需要本应用的未知来源安装授权；下载文件经 FileProvider 的 `content://` URI 和临时读权限交给安装器。
- 隐私流程结束后、登录前检查更新；配置、下载或安装处理异常时沿用原需求，提示后结束更新并继续登录。正常强制状态下仍不可主动关闭。
- 若安装包需携带渠道码，服务端 `url` 应指向相应渠道 APK；更新配置中的 `version` 不负责写入或修改渠道。
- 仅完整下载且通过 APK 包名校验的文件才能交给系统安装器；签名、版本兼容和安装确认由 Android 系统处理。下载中禁止重复发起，关闭非强制窗口或 Activity 销毁时取消下载；长度未知时显示不确定进度，完成后显示 100%。

### 旧字段迁移

| 旧字段 | 新字段 | 变化 |
| --- | --- | --- |
| `isUpdate` | `open` | 是否进入更新流程 |
| `forceUpdate` | `force` | 是否允许关闭正常更新窗口 |
| `downloadUrl` | `url` | 根据 `popup` 决定外部页面或内部 APK 下载 |
| `isPop` | `popup` | 新字段明确具有业务含义：`1` 外部浏览器，`0` 应用内下载 |
| 无 | `width/height/time` | 增加百分比尺寸、自适应高度及更新时间文案 |

客户端与服务端应一起切换至新契约，旧字段不再作为当前更新接口定义。
